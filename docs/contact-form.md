# 問い合わせフォームの送信設定

宛先は `keitaro.tao@borderless-japan.com` に固定。入力者のメールアドレスを Reply-To に設定するので、受信したメールへの返信で連絡できます。入力者への自動返信は送りません。

## 有効化

1. Resend で送信ドメイン（例：`japanfinds.site`）を登録し、案内された DNS レコードを設定して Verified にする。既存の受信用 MX を置き換えないこと。
2. その送信ドメインに限定した送信権限の API キーを作成。
3. Vercel の本プロジェクトの Production に、次のサーバー専用環境変数を設定。
   - `RESEND_API_KEY`: Resend の API キー（Secret）。Git やチャットに貼り付けない。
   - `CONTACT_FROM_EMAIL`: 検証済みドメインの送信元（例：`JAPAN FINDS <contact@japanfinds.site>`）。
4. 再デプロイ後 `/contact` のボタンが「相談内容を送信する」に変わることを確認。
5. テスト問い合わせを送信し、完了表示と宛先での受信・返信先を確認。API 成功は配信サービスによる受付を表すため、実受信も確認する。

両変数が設定されるまでは既存のメールアプリ経由で利用できます。送信失敗時は成功扱いにせず、入力内容を保持して再送とメール連絡を案内します。

## 保護・運用

- 宛先固定、サーバー側入力検証、本文サイズ制限、Origin 検証、ボット向けの隠し項目を実装。
- 再送時は同一内容・同一送信 ID の Idempotency-Key を使い、サービス側の保持期間内で重複送信を防止。
- 公開前に Vercel Firewall で `/api/contact` の POST に IP 単位のレート制限（例：5 回 / 10 分）を設定する。隠し項目と Origin 検証だけでは直接 API を呼ぶボットを防げない。
- 顧客の氏名・メールアドレス・問い合わせ本文を解析イベントやログに記録しない。
- Preview には別の送信キーを使用するか、変数を設定せずメールアプリ経由を使用する。

## ローカル検証

`node --test tests/contact.test.cjs` は TypeScript を一時ディレクトリへ変換し、実メールを送らず API の入力検証・送信失敗・成功・重複防止キーを確認します。
